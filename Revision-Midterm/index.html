Q1

Binding Techniques

B
# DEFINE
x = 10
y = 20
def calculate():
    print(x + y)

# EXECUTE
def execute(func):
    x = 50
    y = 60
    func()

# PASS
x = 30
y = 40
execute(calculate)

Question: Identify the callback; give ad-hoc (DEFINE), deep (PASS) and shallow (EXECUTE) conceptual outputs; explain the actual Python output.

Detailed model answer — step by step

Callback: calculate, because it is passed as the argument func and then invoked by func().

Conceptual techniqueEnvironmentCalculationResult
Ad-hocDEFINE: x=10, y=2010+2030
DeepPASS: x=30, y=4030+4070
ShallowEXECUTE: x=50, y=6050+60110

Actual Python output: 70.

  1. At definition, the function body refers to names x and y, but does not freeze their values.
  2. Before calling execute, the global names are reassigned to 30 and 40.
  3. The local x=50 and y=60 inside execute belong only to that function's local scope.
  4. calculate() resolves x and y in its global scope and prints 70.

Teaching convention: DEFINE/PASS/EXECUTE are conceptual environments used to compare binding strategies; Python does not offer three switchable binding modes.

Concept explained in two sentences

Binding techniques select an environment for resolving variables in the conceptual comparison. Python uses lexical scoping, so calculate reads the reassigned global values rather than execute’s local values.

Q2

Local Binding and Conditional Evaluation

B
(let ((x 5))
  (let ((x 10))
    (if (> x 7) (+ x 3) (- x 3))))

Question: Identify the x used, evaluate the expression and explain shadowing.

Detailed model answer — step by step

Answer: The if uses x = 10; the expression evaluates to 13.

  1. Outer let introduces x=5.
  2. Inner let introduces a new x=10 that shadows x=5.
  3. (> 10 7) is true, so evaluate (+ 10 3).
  4. The final value is 13.

Shadowing: The outer x still exists, but is hidden within the inner scope.

Concept explained in two sentences

Local binding creates a name within a limited scope. A nested binding with the same name hides the outer one within that nested expression.

Q3

Recursive Factorial

B
(define (fact n)
  (if (= n 0) 1 (* n (fact (- n 1)))))
(fact 4)

Question: Identify the base case, trace calls and find the result.

Detailed model answer — step by step

Base case: (= n 0) returns 1.

(fact 4)
= 4 * (fact 3)
= 4 * 3 * (fact 2)
= 4 * 3 * 2 * (fact 1)
= 4 * 3 * 2 * 1 * (fact 0)
= 4 * 3 * 2 * 1 * 1
= 24

Answer: 24. Calls go down to n=0; multiplication happens as calls return.

Concept explained in two sentences

Recursion solves a smaller version of the same problem on each call. The base case stops the calls and permits the result to be calculated.

Q5

BST Construction and Insertion

B

Question: Insert 50, 30, 70, 20, 40, 60, 80 into a BST, then insert 35 and 65 and redraw.

Detailed model answer — step by step

Step 1 – Initial insertion: 50 becomes root; 30 goes left and 70 right. Insert 20 left of 30, 40 right of 30, 60 left of 70, and 80 right of 70.

          50
        /    \
      30      70
     /  \    /  \
   20   40  60   80

Step 2 – Insert 35: 35<50 → left; 35>30 → right; 35<40 → left of 40.

Step 3 – Insert 65: 65>50 → right; 65<70 → left; 65>60 → right of 60.

Final BST (new nodes marked *):

          50
        /    \
      30      70
     /  \    /  \
   20   40  60   80
       /      \
     35*      65*
Concept explained in two sentences

A BST places smaller keys in the left subtree and larger keys in the right subtree. Insertion compares keys from the root until an empty child position is found.

Green nodes: newly inserted values.

An ordinary BST inserts values without rearranging existing nodes. Every new key follows smaller-left and larger-right comparisons.

Q7

Additional BST Practice 2

B

Question: Construct a BST from 45, 25, 65, 15, 35, 55, 75; insert 30 and 60.

Detailed model answer — step by step

Step 1 – Build the original BST: Insert 45 as root, 25 on the left and 65 on the right; then place 15 and 35 under 25, and 55 and 75 under 65.

          45
        /    \
      25      65
     /  \    /  \
   15   35  55   75

Step 2 – Insert 30: 30<45 (left), 30>25 (right), 30<35 (left); add 30 as the left child of 35.

Step 3 – Insert 60: 60>45 (right), 60<65 (left), 60>55 (right); add 60 as the right child of 55.

Final BST (* = newly inserted):

          45
        /    \
      25      65
     /  \    /  \
   15   35  55   75
       /      \
     30*      60*

Check: Every node's left subtree contains smaller values and its right subtree contains larger values.

Concept explained in two sentences

BST insertion follows a comparison path from the root. The inserted value becomes a child at the first empty position on that path.

Q12

Recursive Sum

B
(define (sum n)
  (if (= n 0) 0 (+ n (sum (- n 1)))))
(sum 4)

Question: Identify the base case, trace calls and calculate the result.

Detailed model answer — step by step

Base case: when n=0, return 0.

(sum 4)
= 4 + (sum 3)
= 4 + 3 + (sum 2)
= 4 + 3 + 2 + (sum 1)
= 4 + 3 + 2 + 1 + (sum 0)
= 4 + 3 + 2 + 1 + 0
= 10

Final result: 10.

Concept explained in two sentences

The function repeatedly reduces its argument by one. Its base case prevents infinite recursion and supplies the initial return value.

Q15

AST with Precedence

B

Question: Draw the AST for 8 - 2 * 3 + 1.

Detailed model answer — step by step

Expression: 8 - 2 * 3 + 1.

        +
       / \
      -   1
     / \
    8   *
       / \
      2   3
  1. Multiplication has higher precedence: 2*3 = 6.
  2. Subtraction and addition have equal precedence and are evaluated left-to-right: (8-6)+1.
  3. Therefore + is the root, its left child is -, and the result is 3.
Concept explained in two sentences

Multiplication has higher precedence than addition and subtraction. Addition and subtraction are left-associative, giving (8 - (2 * 3)) + 1.

        +
       / \
      -   1
     / \
    8   *
       / \
      2   3

Q16

Programming Paradigms

C

Question: Explain imperative and OOP approaches, then compare them for a student management system.

Detailed model answer — step by step

(a) Imperative: A program states the sequence of commands that update its state, for example storing marks in variables and updating totals.

(b) Object-oriented: A program groups related data and methods into objects, such as a Student with a name, marks and a calculateGrade() method.

(c) Comparison: In an imperative design, student records and the functions that process them can be separate; in OOP, each Student object groups its data and associated methods.

# Imperative-style example
marks = 80
marks = marks + 5

# Object-oriented example
class Student:
    def __init__(self, marks):
        self.marks = marks
    def add_bonus(self, points):
        self.marks += points
Concept explained in two sentences

Paradigms provide different ways to organise program logic and data. The chosen paradigm influences maintainability and how code is reused.

Q17

Type Checking, Overloading and Overriding

C

Question: Explain static versus dynamic checking, overloading and overriding.

Detailed model answer — step by step

(a) Type checking: Static checking examines type correctness before program execution (for example, Java compilation). Dynamic checking verifies types when operations run (for example, Python raising a TypeError for 10 + "20").

(b) Overloading: Same method name, different parameter signatures, such as Java add(int,int) and add(int,int,int).

(c) Overriding: A subclass replaces the implementation of an inherited method, such as Dog.sound() printing Bark instead of Animal sound.

// Java overloading
int add(int a, int b) { return a+b; }
int add(int a, int b, int c) { return a+b+c; }
# Python overriding
class Animal:
    def sound(self): print("Animal sound")
class Dog(Animal):
    def sound(self): print("Bark")
Dog().sound()  # Bark
Concept explained in two sentences

Type checking helps detect invalid operations. Overloading and overriding support different kinds of polymorphic behaviour.

Q21

Scope and Binding

C

Question: Explain local scope, global scope and lexical scoping.

Detailed model answer — step by step

Local scope: A name introduced within a function is normally available only there.

Global scope: A module-level name can be accessed by functions according to the language's name-resolution rules.

Lexical scope: A function resolves free names from the enclosing scopes where it was defined, not from unrelated local variables in its caller.

x = 10  # global
def show():
    x = 20  # local; shadows global x
    print(x)
show()   # 20
print(x) # 10
Concept explained in two sentences

Scope specifies where a name can be accessed. Lexical scoping uses source-code nesting rather than the caller’s local variables.

Detailed model answer — step by step

Expression: (lambda (x) (+ x y)).

Q23

Functional Programming

C

Question: Explain functional programming, recursion and a base case.

Detailed model answer — step by step

(a) Functional programming: Programs are expressed using functions and expression evaluation, often emphasising immutable data and composition.

(b) Recursion: A function calls itself with a smaller input, for example fact(3) calling fact(2).

(c) Base case: A stopping rule such as fact(0)=1; without reaching it, recursive calls can continue indefinitely or exhaust the call stack.

(define (fact n)
  (if (= n 0) 1 (* n (fact (- n 1)))))
Concept explained in two sentences

Functional code can build solutions by composing and evaluating functions. Recursion needs a stopping condition and progress towards it.

Q24

Data Types

C

Question: Explain aggregate, inductive and variant data types.

Detailed model answer — step by step

(a) Aggregate type: Combines multiple values, for example a record with a student's name and marks or a list of scores.

(b) Inductive type: Defined with base constructors and recursive constructors; a linked list is either empty or a node containing an element and another list.

(c) Variant record: Stores one of several alternatives, usually identified by a tag; for example a Shape can be a Circle(radius) or Rectangle(width,height).

Comparison: Aggregates group fields, inductive types define recursively structured values, and variants express choices between possible forms.

Concept explained in two sentences

Data types provide structures for representing information. Their rules determine how values are built and used.

Q25

Software Engineering and Concurrency

C

Question: Why does language design matter? Define concurrency and compare it with sequential execution.

Detailed model answer — step by step

(a) Language design: Clear syntax, good abstractions and predictable semantics improve maintainability and reduce programming mistakes.

(b) Concurrency: Multiple tasks make progress during overlapping periods, even if they share a single processor.

(c) Sequential vs concurrent: Sequential tasks run one after another; concurrent tasks can interleave or run in parallel depending on the system.

Example: A server can handle multiple client requests concurrently rather than completing every request before starting the next.

Concept explained in two sentences

Good language design helps programmers build dependable software. Concurrency enables overlapping task progress without necessarily requiring simultaneous execution.
