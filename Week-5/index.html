1. Binding, Callbacks, Deep, Shallow & Ad-hoc Binding

Our question: When a callback uses a variable, which environment supplies its value?

1.1 What is binding?

Binding connects a name to a value, function or object.

x = 10
print(x)  # 10

x = 20
print(x)  # 20

The name x first refers to 10, then refers to 20. Binding answers: What does this name refer to?

1.2 What is a callback?

A callback is a function passed to another function so that the receiving function can execute it.

def hello():
    print("Hello Students")

def execute(callback):
    callback()

execute(hello)

Important: hello means the function itself; hello() means run it.

1.3 The three stages of a callback

These are three stages of using one callback, not three different callback types.

1.4 What is an environment?

An environment tells us which variable bindings are available in a particular context.

def room_one():
    x = 10
    print(x)

def room_two():
    x = 20
    print(x)

Each function has its own local x. The same name can refer to different values in different environments.

1.5 Why are callbacks related to binding?

def callback():
    print(x)

The callback uses x without defining it locally. This makes x a free variable. Imagine three different environments around the callback's journey:

These are conceptual binding models for the lesson. Python uses lexical scoping; the three models are not switchable Python execution modes.

3. Conversion, Coercion & Casting

Our question: How can a programming language change a value from one type to another?

3.1 First, remember data types

x = 12      # integer
y = "12"    # string
print(12 + 8)       # 20
print("12" + "8")   # 128

Although 12 and "12" look similar, one is a number and the other is text.

3.2 What is type conversion?

Type conversion changes a value from one type to another. A web form may receive a student's age as text:

age = "20"
# print(age + 1)  # TypeError
age = int(age)
print(age + 1)    # 21
Before"20"

3.3 What is coercion?

Coercion is an implicit (automatic) conversion performed by the language.

x = 3       # integer
y = 2.5     # float
print(x + y)  # 5.5

Python handles the mixed numeric types automatically. You did not explicitly write float(3).

Remember: Coercion = automatic conversion.

3.4 What is casting / explicit conversion?

Explicit conversion means the programmer requests a different type directly. In introductory lessons, this is often called casting.

x = "12"
y = int(x)
print(y + 8)  # 20

4. Parametric Polymorphism

Our question: Can one function work with multiple data types while preserving the same behavior?

4.1 First, what is a function?

A function is a reusable block of code.

def show_number(number):
    print(number)

def show_name(name):
    print(name)

Both functions display a value. Why write separate functions if the behavior is the same?

def show(value):
    print(value)

show(10)
show("Ali")
show(3.5)
10
Ali
3.5

Python demonstrates reuse with different types. For parametric polymorphism specifically, we will use a typed generic function.

4.2 What is polymorphism?

Poly means many; morph means forms. In programming, one interface can work with different types or forms.

NUMBER
42
STRING
"Ali"
BOOLEAN
true

4.3 What is parametric polymorphism?

A generic function uses a type parameter, such as T, so the same logic works with different types.

// TypeScript
function identity<T>(value: T): T {
    return value;
}

Change the type and input.

4.6 Why is it useful?

Without generics, we might repeat the same logic for each type:

function firstNumber(items: number[]): number {
    return items[0];
}
function firstName(items: string[]): string {
    return items[0];
}

With generics, we write it once:

function first<T>(items: T[]): T {
    return items[0];
}
console.log(first<number>([80, 90, 70])); // 80
console.log(first<string>(["Ali", "Sara"])); // Ali

For simplicity, these examples assume the array is non-empty.

4.7 University example

let studentNames = ["Ali", "Sara", "Omar"];
let studentMarks = [85, 90, 75];

console.log(first(studentNames)); // Ali
console.log(first(studentMarks)); // 85

function swap<T>(a: T, b: T): [T, T] {
    return [b, a];
}
console.log(swap<number>(10, 20)); // [20, 10]
console.log(swap<string>("Ali", "Sara")); // ["Sara", "Ali"]

Key idea: A type parameter allows one implementation to preserve type relationships across many different types.

5. Operator & Function Overloading

Our question: Can one operator or function name support different operations?

5.1 What is an operator?

An operator performs an operation on operands (values).

print(4 + 5)                  # 9
print("Hello " + "Students")   # Hello Students

The same + symbol adds numbers or joins strings.

5.2 What is operator overloading?

Operator overloading means one operator has different behavior for different operand types.

NUMBERS
4 + 5
9Addition
STRINGS
"Hi" + "!"
"Hi!"Concatenation
Remember: One operator, different behaviors.

5.3 What is a function?

def show_student(name):
    print(name)

show_student("Ali")

A function is a reusable block of code. Suppose we want the same function name to accept different parameter types.

5.4 What is function overloading?

Function overloading defines multiple functions with the same name but different parameter signatures. Java supports this.

// Java methods inside a class
void print(int value) {
    System.out.println("Number: " + value);
}
void print(String value) {
    System.out.println("Text: " + value);
}
print(25);      // Number: 25
print("Ali");   // Text: Ali

Java chooses a matching overload based on the arguments.

Different numbers of parameters

int add(int a, int b) {
    return a + b;
}
int add(int a, int b, int c) {
    return a + b + c;
}

add(4, 5);      // 9
add(4, 5, 6);   // 15

Changing only the return type is not enough to overload a Java method.

5.5 Operator vs function overloading

Operator overloadingFunction overloading
Same symbol: +Same function name: add()
Behavior depends on operand typesImplementation selected by parameter signature
4 + 5 vs "Hi" + "!"add(4,5) vs add(4,5,6)

5.7 University example

A university application calculates totals from different numbers of assessments:

// Java methods inside a class
int calculateMarks(int quiz, int assignment) {
    return quiz + assignment;
}
int calculateMarks(int quiz, int assignment, int project) {
    return quiz + assignment + project;
}

calculateMarks(8, 15);      // 23
calculateMarks(8, 15, 17);  // 40
Python note: Python supports operator overloading (for example, __add__) but not Java-style signature-based function overloading by repeated def statements. A later definition normally replaces the earlier one.

Key idea: Operator overloading reuses a symbol; function overloading reuses a function name with different parameter signatures.

6. Function Overriding

Our question: Can a child class replace the behavior of a method inherited from its parent?

6.1 First, what is a class?

A class is a blueprint for creating objects.

class Student:
    def show_name(self):
        print("Student: Ali")

student1 = Student()
student1.show_name()
Student: Ali

Student is the class; student1 is an object; show_name() is a method; self refers to the current object.

6.2 What is inheritance?

Inheritance allows a child class to reuse methods and properties of a parent class.

class UniversityMember:
    def show_role(self):
        print("University Member")

class Student(UniversityMember):
    pass

Student().show_role()  # University Member
Parent classUniversityMember
show_role()
→
Child classStudent
Inherits method

6.3 What is overriding?

Method overriding occurs when a child class provides its own implementation of an inherited method.

class UniversityMember:
    def show_role(self):
        print("University Member")

class Student(UniversityMember):
    def show_role(self):
        print("Student")

UniversityMember().show_role()  # University Member
Student().show_role()           # Student

The child replaces the inherited behavior for its own objects.

6.4 Animal example from the lesson

class Animal:
    def speak(self):
        return "Sound"

class Dog(Animal):
    def speak(self):
        return "Woof"

class Cat(Animal):
    def speak(self):
        return "Meow"

print(Animal().speak())  # Sound
print(Dog().speak())     # Woof
print(Cat().speak())     # Meow
Parent: Animal
speak() → "Sound"
Child: Dogspeak() → "Woof"
Child: Catspeak() → "Meow"

The method name is always speak(); the result depends on the object's actual class.

6.5 How does Python choose the method?

When you call dog.speak(), Python uses the implementation in Dog. When you call cat.speak(), it uses Cat. This selection is called method dispatch. If a child does not override the method, it can inherit the parent implementation.

The same display_role() function works with different objects because each child class overrides show_role().

7. Type Inference

Our question: Can the programming language determine a type automatically without an explicit type annotation?

7.1 First, remember data types

age = 20
name = "Ali"
gpa = 3.5
passed = True

Values have types: integer, string, float and Boolean. In TypeScript, we can explicitly annotate types:

let age: number = 20;
let name: string = "Ali";

But TypeScript often determines the types without those annotations.

7.2 What is type inference?

Type inference means the language determines a variable or expression's type from information in the code.

let age = 20;  // TypeScript infers: number
Programmer writeslet age = 20;
→
Compiler examinesValue 20
→
Inferred typenumber
Remember: The compiler figures out the type without requiring you to write it explicitly.

7.3 How does it work?

let count = 12;          // number
let studentName = "Ali"; // string
let passed = true;       // boolean

7.4 Why is inference useful?

Explicit types

let studentName: string = "Ali";
let studentAge: number = 21;
let studentGPA: number = 3.5;
let isRegistered: boolean = true;

Inferred types

let studentName = "Ali";
let studentAge = 21;
let studentGPA = 3.5;

The second version is shorter, but TypeScript still has type information.

7.5 Inference vs type checking

let age = 20;     // inference: number
age = "Hello";    // static type error

Inference determines the type; checking verifies whether assignments and operations follow the type rules.
