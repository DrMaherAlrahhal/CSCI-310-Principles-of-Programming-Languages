Lab 1 · The big picture

How does your idea reach the CPU?

A programming language expresses our solution as source code. The processor executes machine instructions, not English-like Python statements.

💡 Problem→⌨️ Source code→⚙️ Translation / interpretation→🖥️ CPU→✅ Result
Try it: change the student's mark

A simple imperative Python decision

The program's meaning depends on its condition. The CPU cannot decide whether your university's pass rule is the one you intended.

Lab 5 · One problem, five styles
Same problem. Different ways to organize the solution.
Our shared problem: determine Pass or Fail from a mark, using the rule mark ≥ 60. Change the style to compare how the idea is expressed.
Object-oriented example
A Student object can contain a mark (data) and a result() method (behavior).
Bottom-up example
Build read_mark(), check_result() and display_result() separately, test them, then combine.
Bottom-up is a development strategy; the other four are common programming paradigms. A real project may combine multiple approaches.


Lab 6 · AI coding assistant
AI generated a working program. Is it correct?
The slides show a program using score > 60 although the expected rule is score ≥ 60. That single missing equals sign changes the result at the boundary.
Test the boundary
def predict_result(score):
    return "Pass" if score > 60 else "Fail"
Small task
Clear requirements and fewer details often make code generation easier to verify.
Large system
Security, database, user management, reporting and deployment require careful specification, testing and modification.
Human: problem owner and verifier. AI: coding assistant. Always check boundary cases, requirements and behavior.
