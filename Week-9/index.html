0. First: What is control flow?

Main idea

Control flow means the order in which a program runs its instructions.

  • Normally, a program runs from top to bottom.
  • Sometimes we want to skip an instruction, jump somewhere else, or handle an error.
  • This week we learn five ways programs change their normal execution order.
Normal Python example
1  print("A")
2  print("B")
3  print("C")
Output: A → B → C

Execution order: 1 → 2 → 3.

Think

If a program jumps from Line 1 directly to Line 3, what happens to Line 2?

Line 2 is skipped. Only Lines 1 and 3 execute.

1. Continuations — Scheme call/cc

Main idea

A continuation represents the task waiting to be completed.

  • call/cc remembers the waiting task.
  • It calls a function and gives that function a special parameter, which we name k.
  • When the function calls (k 8), Scheme uses 8 to complete the waiting task.
  • Code after that call to k is not executed in this example.

Simple sentence: “Here is k. When you give k a number, I will use that number to finish the task waiting here.”

Example with x and y — no lambda

Scheme code
1  (define x 5)
2  (define y 3)
3  (define (f k)
4    (k (+ x y))
5    (* x y))
6  (display (call/cc f))
Output: 8

f = function name. k = parameter that receives the saved continuation.

Execution order

  1. Line 1: Set x = 5.
  2. Line 2: Set y = 3.
  3. Line 3: Define function f. Its body does not run yet.
  4. Line 6: display is waiting for a number. call/cc remembers that task and gives k to f.
  5. Line 4: Calculate 5 + 3 = 8. Calling (k 8) gives 8 to the waiting task.
  6. Line 6: The waiting task prints 8.
  7. Line 5: Not reached. (* x y) is skipped because control transferred to the saved continuation.
1→2→3→6→4→65 skipped
Why does k go to display?

Look at (display (call/cc f)). The program is waiting to print the result of call/cc. That is the task k remembers. If the waiting task were multiplication by 2 and then printing, the final output would be 16.

Interactive example — change x and y

 

Output: 8. Multiplication is skipped.
Predict the output

What if Line 4 becomes (k (* x y))?

The output becomes 15 because 5 × 3 = 15. Calling k supplies 15 to the waiting display.
Think more deeply

What if Line 4 is only (+ x y), without k?

The program continues to Line 5. The last expression is multiplication, so the output is 15.

2. Nonlocal Transfer — Jump across functions

Main idea

Sometimes one function calls another function, and the second function needs to transfer control directly to an earlier saved task.

  • A normal function usually returns to the function that called it.
  • A continuation can transfer control to a saved task without completing intermediate calculations.
  • This is called a nonlocal transfer of control.

Example — f is called from g

Scheme code · no lambda
1  (define x 5)
2  (define y 3)
3  (define (f k)
4    (k (+ x y)))
5  (define (g k)
6    (* 2 (f k)))
7  (display (call/cc g))
Output: 8 (not 16)
  1. Lines 1–2: Set x = 5, y = 3.
  2. Lines 3 and 5: Define functions f and g.
  3. Line 7: call/cc gives k to g. The waiting task is to print a number.
  4. Line 6: g calls f and intends to multiply its result by 2.
  5. Line 4: f calculates 8 and calls (k 8).
  6. Line 7: Scheme prints 8.
  7. Line 6: Multiplication by 2 is not completed.
7→6→4→7× 2 skipped
Normal return
(define (f) 8)
(define (g) (* 2 (f)))
(display (g))
Output: 16
Continuation
(define (f k) (k 8))
(define (g k) (* 2 (f k)))
(display (call/cc g))
Output: 8
Predict

If Line 4 becomes (k (* x y)), will the result be 15 or 30?

15. f gives 15 to the saved task. The multiplication by 2 inside g is skipped.

3. goto in C — Jump to a label

Main idea

goto tells C: “Continue from the label I name.”

  • goto result; = jump to the label result:.
  • Instructions between the jump and destination can be skipped.
  • In C, a goto label must be inside the same function.
  • For normal loops and decisions, for, while, and if are usually easier to read.
C code
1  #include <stdio.h>
2  int main(void) {
3      int x = 5;
4      int y = 3;
5      printf("Start\n");
6      goto result;
7      printf("Middle\n");
8  result:
9      printf("%d\n", x + y);
10     return 0;
11 }
Start
8
  1. Before execution: The preprocessor handles Line 1.
  2. Line 2: Start main.
  3. Lines 3–4: Set x = 5, y = 3.
  4. Line 5: Print Start.
  5. Line 6: Jump to the label result:.
  6. Line 7: Skipped. Middle is not printed.
  7. Lines 8–9: Continue at result and print 8.
  8. Line 10: Finish the function.
2→3→4→5→6→8→9→107 skipped

Interactive example — with or without goto

Start
8
Predict

If we remove goto result;, will result: still run?

Yes. A label does not block execution. Without goto, the program runs top to bottom and prints Start, Middle, 8.

4. setjmp and longjmp in C

Main idea

Think of a checkpoint in a game.

  • setjmp = remember a point in the running program.
  • The first time setjmp runs, it returns 0.
  • longjmp = transfer control back to that remembered point.
  • After longjmp(point, 8), the saved setjmp returns 8.
  • If longjmp is given 0, the resumed setjmp returns 1 instead.
C code · two variables
1  #include <stdio.h>
2  #include <setjmp.h>
3  jmp_buf point;
4  void f(void) {
5      int x = 5;
6      int y = 3;
7      printf("Inside f\n");
8      longjmp(point, x + y);
9      printf("After jump\n");
10 }
11 int main(void) {
12     if (setjmp(point) == 0) {
13         printf("Start\n");
14         f();
15         printf("Finish\n");
16     } else {
17         printf("Returned to main\n");
18     }
19     return 0;
20 }
Start
Inside f
Returned to main

Execution order

  1. Lines 1–3: Include declarations and create the storage named point before main begins.
  2. Line 11: Start main.
  3. Line 12: setjmp(point) remembers the point and returns 0. The if branch runs.
  4. Line 13: Print Start.
  5. Line 14: Call function f.
  6. Lines 5–7: Set x = 5, y = 3 and print Inside f.
  7. Line 8: Calculate 8. longjmp(point, 8) transfers control back to Line 12.
  8. Line 12 again: Now setjmp returns 8. The condition 8 == 0 is false.
  9. Lines 16–17: Execute the else branch and print Returned to main.
  10. Line 19: Finish the program.
  11. Lines 9 and 15: Not reached. They are skipped by the nonlocal transfer.
12→13→14→5–8→12 again→16–17→19

Interactive example — value sent to longjmp

longjmp(point, 8) → setjmp returns 8 → else branch runs.
Important safety rule

Only use longjmp with a valid saved environment while the function containing setjmp is still active. It skips normal function returns and cleanup. Some local variables modified after setjmp may have indeterminate values after longjmp.

Predict

What happens with longjmp(point, 0)?

The saved setjmp returns 1, not 0. The else branch still runs.

5. Exception Handling in Python

Main idea

When something goes wrong, Python can handle the error instead of ending the whole program.

  • try = run code that might cause an error.
  • except = handle a matching error.
  • finally = run the final instructions whether the code succeeded or failed.

Simple sentence: “Try the calculation. If it fails, print a helpful message. Then finish the task.”

Python code
1  x = 10
2  y = 0
3  try:
4      result = x / y
5      print("Result:", result)
6  except ZeroDivisionError:
7      print("Cannot divide by zero")
8  finally:
9      print("Calculation finished")
10 print("Program continues")
Cannot divide by zero
Calculation finished
Program continues

Execution order when y = 0

  1. Lines 1–2: Set x = 10, y = 0.
  2. Line 3: Enter the try block.
  3. Line 4: Division by zero raises ZeroDivisionError.
  4. Line 5: Skipped because Line 4 failed.
  5. Lines 6–7: Handle the error and print Cannot divide by zero.
  6. Lines 8–9: Run finally and print Calculation finished.
  7. Line 10: Print Program continues.
1→2→3→4→6–7→8–9→105 skipped

Interactive example — change y

Cannot divide by zero
Calculation finished
Program continues

Path: try → except → finally → continue

Why use finally?

Some tasks should happen even when an error occurs, such as closing an opened file or releasing a resource. In Python, with is often an even better way to manage files.

Predict

If y = 2, which lines are skipped?

Lines 6–7 (the except block) are skipped because no error occurs. The output is Result: 5.0, Calculation finished, and Program continues.

Final assessment — check your understanding

Select an answer for each question. You will see feedback immediately.

Written questions

Question 1

Explain why the continuation example prints 8 instead of 15. Mention Line 4 and Line 5.

Line 4 calculates 8 and calls k. That gives 8 to the saved printing task. The program does not continue to Line 5, so multiplication is skipped.
Question 2

Explain the difference between goto and longjmp.

goto jumps to a label within the same function. longjmp transfers control to an environment saved earlier by setjmp, possibly across active function calls.
Question 3

Why does Python run finally even after catching an error?

finally contains actions that must run when leaving the try statement, such as cleanup, whether the try block succeeds or raises an error.
