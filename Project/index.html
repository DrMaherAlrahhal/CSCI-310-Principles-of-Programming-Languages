Build the working application

Frontend: The interface users see and interact with.

Backend: The logic that processes input and manages data.

Data storage: A file or database that keeps information for later use.

Validation: Checking user input before processing it.

Filtering: Showing only records that match a condition.

Required application features

  1. At least four functional pages or screens.
  2. Forms and user input.
  3. Data storage and retrieval.
  4. Search or filtering.
  5. Calculations or decision-making.
  6. Clear navigation and error messages.

Simple learning example: validate a mark

def valid_mark(value):
    try:
        mark = float(value)
        return 0 <= mark <= 100
    except (TypeError, ValueError):
        return False

print(valid_mark("85"))   # True
print(valid_mark("abc"))  # False

This is only a small example of validation; it is not the complete application.

Task 43 marks · CLO3, CLO4

Find programming paradigms in your code

Imperative: Instructions change values step by step using assignments, loops and conditions.

Functional: Functions transform data and return results.

Object-oriented: Classes organise related data and behaviour.

Logic-oriented: Facts and rules determine conclusions.

Short learning examples

Imperative programming example
passed = 0
for mark in [45, 60, 80]:
    if mark >= 50:
        passed += 1
print(passed)  # 2

A loop updates the variable passed step by step.

Functional programming example
marks = [45, 60, 80]
passed = list(filter(lambda m: m >= 50, marks))
print(len(passed))  # 2

A function filters the original list to produce a result.

Object-oriented programming example
class Student:
    def __init__(self, mark):
        self.mark = mark

    def passed(self):
        return self.mark >= 50

print(Student(80).passed())  # True

The class keeps a student's data and behaviour together.

Rule-based logic example
def eligible(mark, attendance):
    return mark >= 50 and attendance >= 75

print(eligible(80, 90))  # True

This illustrates a decision rule; it is not a full logic-programming language implementation.

What to produce: Identify at least two paradigms used in your actual project, show the relevant code, and explain why each approach is suitable.
Task 54 marks · CLO5

Build a mini-interpreter

Mini-language: A small set of expressions with clearly defined meanings.

Input: The expression entered by the user as text.

Parsing: Identifying the command and its arguments.

Evaluation: Calculating the result of a valid expression.

Error handling: Explaining why an expression cannot be evaluated.

Interpreter process

Text input → recognise command → read arguments → validate → calculate → display result

Try a working mini-interpreter

This learning demonstration supports AVERAGE, PASS and ELIGIBLE; your group must implement and explain its own interpreter.

Result: 80

Example Python implementation of parsing

import re

def interpret(text):
    match = re.fullmatch(r"([A-Z]+)\((.*)\)", text.strip())
    if not match:
        return "Invalid expression"

    command, raw_args = match.groups()
    args = [part.strip() for part in raw_args.split(",")]
    if command == "PASS" and len(args) == 1:
        try:
            return float(args[0]) >= 50
        except ValueError:
            return "Invalid mark"
    return "Unsupported command"

print(interpret("PASS(65)"))  # True

This code intentionally implements only one command as a learning example. Extend the interpreter for your project's defined expressions and test malformed inputs. Avoid using unrestricted eval() on user input.

What should you test?

PASS(65)True
ELIGIBLE(45,TRUE)True (illustrative rule: 45+ and TRUE)

The official remit gives these expressions as examples; your group should define and document the precise rules used in its own mini-language.

What to produce: A text-input interpreter that recognises commands and arguments, evaluates valid expressions, handles errors, and can be explained in a live demonstration.
